# User stories Student Task Manager

**Автор:** Руслан Махмадов  
**Група:** 31 КНС  
**Практична робота №9:** User stories та критерії приймання

## Продукт і актор

Student Task Manager допомагає студенту зберігати навчальні завдання з різних дисциплін, бачити строки здачі й контролювати виконання.

Основний актор — студент коледжу або університету, який самостійно веде список власних навчальних завдань. Саме він створює записи, переглядає їх, змінює дані та позначає виконання. Для поточного MVP достатньо цього актора.

## Межі роботи

Історії охоплюють чотири функції зафіксованого MVP. Їх звірено з [вимогами після ПР8](requirements.md) та [описом продукту](product-description.md). Сортування FR-05 відкладено на наступні версії. Збереження даних і перевірка введення є спільними умовами приймання відповідних сценаріїв.

## US-01 Створення навчального завдання

**Як студент, я хочу додати завдання з назвою, дисципліною та датою здачі, щоб зафіксувати отриману роботу й бачити, до якого дня її потрібно підготувати.**

- **Пріоритет:** високий.
- **Функція MVP:** створення завдання.
- **Пов’язана вимога:** [FR-01](requirements.md#fr-01-створення-завдання).
- **Додаткові умови:** NFR-01 і NFR-02.

### Критерії приймання

1. Після збереження назви «Звіт», дисципліни «Інформатика» та дати 2026-11-20 у списку з’являється рівно один запис із цими даними та статусом «Не виконано».
2. Якщо назва або дисципліна містить лише пробіли чи дата дорівнює 2026-02-30, збереження залишає список без змін, а повідомлення вказує некоректне поле.

## US-02 Перегляд навчальних завдань

**Як студент, я хочу бачити спільний список завдань із дисциплінами, строками та статусами, щоб визначити, які роботи ще потрібно виконати.**

- **Пріоритет:** високий.
- **Функція MVP:** перегляд списку завдань.
- **Пов’язана вимога:** [FR-02](requirements.md#fr-02-перегляд-списку-завдань).
- **Додаткова умова:** NFR-01.

### Критерії приймання

1. Після відкриття списку з двома збереженими завданнями студент бачить обидва записи та назву, дисципліну, дату здачі й поточний статус кожного.
2. Якщо збережених завдань немає, на екрані відображається повідомлення «Немає завдань».

## US-03 Редагування даних завдання

**Як студент, я хочу змінювати назву, дисципліну або дату здачі вибраного завдання, щоб план залишався актуальним після уточнення умов роботи чи перенесення строку викладачем.**

- **Пріоритет:** високий.
- **Функція MVP:** редагування завдання.
- **Пов’язана вимога:** [FR-03](requirements.md#fr-03-редагування-завдання).
- **Додаткові умови:** NFR-01 і NFR-02.

### Критерії приймання

1. Після зміни дати першого з двох завдань на 2026-11-21 змінюється лише ця дата у вибраному записі. Його назва, дисципліна й статус, а також другий запис зберігають попередні значення.
2. Після збереження змін і штатного повторного запуску застосунку на тому самому пристрої відредагована дата залишається 2026-11-21.

## US-04 Позначення виконаного завдання

**Як студент, я хочу позначити вибране завдання виконаним, щоб відрізняти завершені роботи від тих, які ще потребують уваги.**

- **Пріоритет:** високий.
- **Функція MVP:** позначення виконання.
- **Пов’язана вимога:** [FR-04](requirements.md#fr-04-позначення-виконання).
- **Додаткова умова:** NFR-01.

### Критерії приймання

1. Після позначення одного з двох невиконаних завдань як виконаного його статус у списку стає «Виконано», а статус іншого запису залишається «Не виконано».
2. Після штатного закриття й повторного запуску застосунку на тому самому пристрої обраний запис має статус «Виконано».

## Перевірка якості історій

Для всіх чотирьох історій визначено актора, конкретну дію та користь. Кожна історія охоплює одну функцію MVP, має пріоритет, посилання на функціональну вимогу і два спостережувані критерії приймання. Критерії описують очікувану поведінку майбутнього застосунку.

## Висновок

Визначено основного актора Student Task Manager — студента. Створено чотири user stories для всіх функцій поточного MVP та вісім критеріїв приймання. Для кожної історії вказано пріоритет і пов’язану вимогу FR-01–FR-04. Історії узгоджено з результатами перевірки вимог у ПР8.
