# MVP Student Task Manager

Руслан Махмадов · 31 КНС · Практична робота №16

Мета — дати студенту змогу вести список навчальних робіт із дисциплінами, строками здачі та статусами. Реалізація спирається на [вимоги](requirements.md), [UC-01](use-case.md) та [прототип](prototype.md).

| Код | Функція |
| --- | --- |
| MVP-01 | Показати актуальний список або повідомлення про відсутність записів |
| MVP-02 | Додати активне завдання з назвою, дисципліною та датою |
| MVP-03 | Редагувати вибране завдання зі збереженням його ідентифікатора |
| MVP-04 | Позначити завдання виконаним або повернути до активних |
| MVP-05 | Видалити вибраний запис |
| MVP-06 | Переглядати всі, активні або виконані записи |
| MVP-07 | Відхилити порожні й пробільні назви при створенні та редагуванні |

Дані зберігаються в localStorage браузера. Вхід, синхронізація між пристроями, сповіщення та сортування за строком відкладено. Застосунок відкривається з app/index.html. Команди клонування наведено в [README](../README.md).

## Результати перевірок

Виконано JavaScript із фактичного HTML у Node.js з імітацією DOM і localStorage. Перевірено обробники форми та кнопок і зміни списку. Запуск браузерного інтерфейсу в цьому середовищі заблокував збій Chromium під час старту.

## Самостійна робота — завершена версія

Робочий застосунок використовує FastAPI та SQLite. Таблиці користувачів, категорій, завдань і сесій створюються скриптом [schema.sql](../server/schema.sql). Паролі зберігаються як хеші scrypt з випадковою сіллю. Сесії відкликаються при виході. Кожен запит до конкретного завдання перевіряє ідентифікатор власника.

Пошук за назвою поєднується з фільтрами стану, категорії та пріоритету. Сортування доступне за датою й пріоритетом. Прострочені активні записи позначено окремо. Категорії наперед визначені.

### Перевірка завершеної версії

Запити виконано до запущеного Uvicorn з окремою тимчасовою SQLite та двома незалежними сховищами cookie. Для перевірки збереження процес сервера зупинено й запущено з тією самою базою.

| № | Перевірка | Очікувано | Фактично | Статус |
| --- | --- | --- | --- | --- |
| 1 | Запуск | Відкривається головна сторінка | Сервер запущено, GET / повернув 200 | Пройдено |
| 2 | Реєстрація | Створено користувача | HTTP 201 | Пройдено |
| 3 | Дублікат адреси | Повторна адреса відхилена | HTTP 409 навіть з іншим регістром | Пройдено |
| 4 | Вхід | Повертається профіль А | HTTP 200, ім’я відповідає акаунту А | Пройдено |
| 5 | Хибний пароль | Відмова | HTTP 401 | Пройдено |
| 6 | Створення | З’являється активне завдання | HTTP 201, назва й стан відповідають запиту | Пройдено |
| 7 | Пробільна назва | Запис не додається | HTTP 422, у списку один попередній запис | Пройдено |
| 8 | Редагування | Змінюються всі п’ять полів, ID збережено | HTTP 200, усі значення збіглися, ID той самий | Пройдено |
| 9 | Зміна стану | Активне → виконане → активне | У відповідях стан 0 → 1 → 0 | Пройдено |
| 10 | Видалення | Видаляється лише вибраний запис | HTTP 204, інший запис доступний | Пройдено |
| 11 | Пошук і три фільтри | Збіг за всіма умовами | Повернувся лише очікуваний запис | Пройдено |
| 12 | Сортування | Правильний порядок за датою та пріоритетом | Перший запис змінився відповідно до параметра | Пройдено |
| 13 | Ізоляція | Б не бачить і не змінює записи А | Список Б порожній. Чужі GET, PUT, PATCH і DELETE повернули 404 | Пройдено |
| 14 | Вихід | Захищені операції недоступні | Вихід повернув 200, наступні GET і POST повернули 401 | Пройдено |
| 15 | Запит без захисного заголовка | Запит відхилено | HTTP 403, сесія збереглася | Пройдено |
| 16 | Пароль у базі | Зберігається сольовий хеш | У полі password_hash є сіль і хеш, введений пароль відсутній | Пройдено |
| 17 | Перезапуск | Запис зберігається | Після нового запуску й входу запис із відредагованою назвою доступний | Пройдено |
| 18 | Вузький екран | Поля стають в одну колонку, кнопки переносяться | У CSS є відповідні правила. Візуальну перевірку не виконано | Заблоковано |

### Демонстрація двох користувачів

Зареєструйте А, увійдіть і створіть «Практична робота». В іншому профілі браузера зареєструйте Б. Список Б буде порожнім. Поверніться до А та відкрийте створений запис. Результати прямої перевірки прав наведено у рядку 13.
